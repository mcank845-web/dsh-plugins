### 一、`dsha-tool-hash`

#### concern

**C1 · 描述说"相对工作区的路径"，实际按 `process.cwd()` 解析**
实测：在 `_selftest` 目录下调 `hash(path: '_t_rel.txt')` **成功**，说明 Node 的 `stat()` 是按
**进程 cwd** 解析的，不是会话工作区。DSH 宿主的 cwd 通常不是用户工作区 ⇒ 模型传相对路径会
指向一个莫名其妙的位置，甚至"成功"算错文件。
**建议**：description 改成 **「绝对路径」**（最稳妥，不用猜宿主 cwd）；如果一定要支持相对路径，
得从 `exec`/`ctx` 拿到会话 workspace 再拼，别依赖 cwd。

**C2 · 非普通文件会一直挂着（无超时、无大小上限）**
`stat()` 只挡了目录。FIFO、`/dev/zero`、正在被写入的超大文件都能通过检查，然后
`createReadStream` 永不 `end` ⇒ 工具挂死到宿主超时。
**建议**：`stat` 后加 `if (!st.isFile()) throw`；可选再挂 `AbortSignal.timeout()` 或加一个
"读了 N 秒还没完就抛"的兜底。（我这边是 Windows，FIFO 那条**没法实测**，属于按代码判断。）

#### nit

**N1** · `render(_args, value)` 的 `_args` 未使用，无害。
**N2** · README 的例子全是 `/sdcard/...`，PC 上照抄必失败；建议加一句"PC 用你自己的工作区路径"。
**N3** · 输出里的 `path` 原样回显用户传入的字符串；建议回显 `resolve()` 后的绝对路径，
方便人核对"到底算的是哪个文件"。

### 二、`dsha-tool-listen`

#### concern

**C3 · 只检查了 HTTP 层，没检查业务错误信封（最高优先，但需你确认）**
代码只做了 `if (!res.ok)`。MiniMax 系列接口**常见**做法是 200 响应里带
`base_resp: {status_code, status_msg}`，业务错误时 `status_code != 0`、`text` 为空。
若确实如此 ⇒ **失败会被当成成功**，模型拿到 `text: ""` 也不知道为什么。
**我无 key，这条验不到，请你在手机端用一个错误请求确认一次**（比如故意传非音频文件）。
**建议**：解析后先查，非 0 就抛：
```js
if (data.base_resp && data.base_resp.status_code !== 0)
  throw new Error(`ASR 业务错误 ${data.base_resp.status_code}: ${data.base_resp.status_msg}`)
```

**C4 · 文件名取法在 Windows 路径下失效**
`args.path.split('/').pop()`：实测 `'C:\\Users\\x\\a.mp3'` → 结果就是**整个路径**
（`"C:\Users\x\a.mp3"`），会当成文件名上传。
**建议**：`import { basename } from 'node:path'`，用 `basename(args.path)`。实测可用。

**C5 · `/root/.minimax_key` 写死**
PC 上必然失败，且这个插件和 `hash` 不一样，README 没说它 PC 可用。
**建议**：`process.env.MINIMAX_API_KEY` 优先，其次 `join(homedir(), '.minimax_key')`。

**C6 · 校验顺序：key 在文件之前**
`apiKey()` 在 `stat()` 前面 ⇒ **key 缺失会掩盖"文件不存在"**，报错指向 key，
模型会去查 key 而不是查路径。实测确认：不存在的路径 + 无 key 时，报的是
`读不到 API key：/root/.minimax_key`。
**建议**：先查文件（`stat` + `isFile` + 大小），再读 key。

**C7 · 整文件读进内存**
`readFile` → 50 MB buffer，再 `new Blob([buf])` 又拷一份，峰值可能 100–150 MB。
手机 11 GB 内存扛得住，但没必要。
**建议**：`fs.openAsBlob(path)`（Node ≥19.8；本机 24.21 实测有）直接交给 `fetch`，流式、省一半以上。

**C8 · Blob 没有 MIME**
`new Blob([buf])` 的 `type` 是空串（实测），上传按 `application/octet-stream`。
不少 ASR 接口按类型/扩展名判格式，可能被拒。
**建议**：按扩展名映射 MIME，如 `new Blob([buf], { type: 'audio/mpeg' })`。

**C9 · 无重试**
429 / 5xx 直接抛。
**建议**：对 429/500/502/503 做 1–2 次指数退避；其它状态码不要重试。

**C10 · `apiKey()` 吞掉真实原因**
`catch { return '' }` ⇒ 权限问题、路径问题全变成"读不到 API key"。
**建议**：保留 `e.code`（ENOENT / EACCES 分开报）。

#### nit

**N4** · 文档写 ≤500 秒，但代码只校验 ≤50 MB，**没有时长校验**；超长文件由服务端拒（然后被 C3 掩盖）。
**N5** · `speakers` 恒可能为 0（verbose 也不一定带说话人），但 render 照样显示"说话人 0"，易误读；
建议 0 时显示"未知"。
**N6** · `text` 模式下 `segments` 恒空，render 显示"0 段"，同上。
**N7** · 缺 README 和 `.gitignore`（`hash` 两个都有）。
**N8** · `MAX_MB` 硬编码，建议允许 config 覆盖。

### 三、schema 合规 —— **两个都通过**（附实测依据，可直接补进文档）

我把 dsh 的校验规则逐条撞了一遍，报错原文如下（**建议补进 `02-插件规范.md`**）：

| 写法 | 实际报错 |
|---|---|
| 属性级 `required: false` | `parameters.a.required must be true when present` |
| 对象级 `required: true` 或 `required: [...]` | `schema.required is not supported by the value schema DSL` |
| **缺 `additionalProperties`** | **`schema.additionalProperties must be explicitly true or false`** |
| 参数 shorthand 没写 `type` | `parameters.b.type must be string/number/integer/boolean/null/array/object/json, or use oneOf` |

⚠️ **最后一条文档里没有**：`additionalProperties` **必须显式写**，不能省。
两个插件现在都写了 `false`，所以没事；但下一个人很可能省掉然后报错。

另外两条实测确认：
- 参数 DSL 会在 `defineTool()` 时**规范化**成标准 JSON Schema（`{type:'object',properties,required}`），
  `required: true` 会被收进 `required` 数组 —— 写 shorthand 是对的。
- **`enum` 在 execute 期真的会校验**：直调 `execute({algorithm:'sha512'})` 被拒
  （`"algorithm" must be one of [...]`），所以不要在实现里再手动校验枚举。

### 三、这轮新发现的两条 nit（都不影响功能）

**N9 · `listen` 文件头注释过时**
```js
// 后端：MiniMax ASR（asr-1.0），key 读 /root/.minimax_key   ← 已不是唯一来源
```
现在是「环境变量 → `~/.minimax_key` → `/root/.minimax_key`」三级。建议同步改注释，否则下一个人看头注释会以为只认那个文件。

**N10 · 手机上 `KEY_FILES` 两项是同一个路径**
```js
const KEY_FILES = [join(homedir(), '.minimax_key'), '/root/.minimax_key']
```
手机上 `homedir()` 就是 `/root` ⇒ 两项完全相同 ⇒ key 缺失时报错会变成
`已试：/root/.minimax_key(ENOENT) / /root/.minimax_key(ENOENT)`，**同一路径出现两遍**。
**建议**：去重，例如
```js
const KEY_FILES = [...new Set([join(homedir(), '.minimax_key'), '/root/.minimax_key'])]
```
（这是读代码推出来的，**我没在手机上实测**；你那边跑一次错误 key 就能看到。）

**另有一处小的顺序问题（不算 nit，算备注）**：`apiKey()` 现在排在 `stat`/`isFile` 之后 ✅ 正确，
但**排在大小检查之前** —— 所以"51 MB 且没配 key"时报的是 key 错，不是大小超限。
影响很小，你要顺手调就把大小检查提到 `apiKey()` 前面。
